## Query Pattern: Claude Reads Vault Structure

Instead of custom index, Claude:

1. **Reads realm-vault folder structure** (cheap, just paths)
   ```
   → See all decision/, function/, class/ files
   → Build in-memory graph from filenames
   ```

2. **Reads frontmatter + compressed sections** (cheap, ~20 tokens per file)
   ```yaml
   id: validateUser
   type: function
   tags: [auth, critical-path]
   depends_on: [token-codec, user-db]  # Can also be [[links]]
   ```

3. **Follows [[wiki-links]] to build subgraph** (as needed)
   ```
   User asks: "Tell me about user validation"
   
   Claude:
   - Loads validateUser.md (compressed) ~20 tokens
   - Reads depends_on: [[TokenCodec]], [[UserDB]]
   - Loads those files (compressed) ~20 tokens each
   - Reads inbound backlinks: [[AuthService]], [[LoginUI]]
   - Loads those (compressed) ~20 tokens each
   - Total: ~80-100 tokens for full auth subgraph
   ```

4. **User can expand via Obsidian**
   - Graph view shows the visual knowledge map
   - Backlinks panel shows everything that links TO this node
   - Outbound links show everything this node links to
   - Tags filter by #auth, #critical-path, etc
   - Search finds by function name, decision name, class name

## Claude Integration: Compressed Extract

When Claude needs context, use the **realm-recall** skill:

```bash
# Pull by tag (Obsidian native)
realm-recall @auth --compressed
# → Finds all files tagged #auth in frontmatter
# → Loads each file's compressed summary block
# → Cost: ~100-150 tokens (10 nodes × 15 tokens avg)
# → User reviews in Obsidian graph, can expand individual nodes

# Pull by function name (via alias or id)
realm-recall function:validateUser --compressed
# → Loads validateUser.md compressed section
# → Follows [[depends_on]] + [[called_by]] links
# → Cost: ~50-80 tokens for full subgraph

# Pull by decision
realm-recall decision:auth-flow --compressed
# → Loads decision compressed
# → Shows implementations via [[AuthService]], [[validateUser]]
# → Cost: ~60-100 tokens including implementations

# Show graph trace (no content, just structure)
realm-recall @auth --graph-only
# → Returns link structure only (frontmatter links)
# → User visually explores in Obsidian
# → Cost: <10 tokens
```

## Sync Surface: Obsidian IS the Vault

**No separate index needed.** The vault itself is the graph:

- **Backward sync** (Claude → Obsidian): Write `decisions/new-decision.md`, `discoveries/session-note.md` → Obsidian auto-picks them up, backlinks auto-populate
- **Forward sync** (Obsidian → Claude): User manually links nodes in Obsidian, frontier-phase or realm-recall reads the structure
- **Visual sync**: User opens Obsidian graph view, sees knowledge tree live
- **Link sync**: User updates [[references]] in Obsidian, next Claude pull reflects new connections

## Implementation Plan

1. **Folder structure** in Obsidian vault (decisions/, functions/, classes/, systems/, discoveries/)
2. **Frontmatter schema** (id, type, tags, status, created, updated)
3. **Compressed + Full** pattern (two sections in each .md file)
4. **Alias convention**: filename = `node-{id}.md`, alias = `{id}` for clean linking
5. **realm-recall skill**: Read vault structure + frontmatter + follow [[links]] + extract subgraph
6. **realm-phase enhancement**: Scan repo → write new nodes to vault → Obsidian auto-links backlinks
7. **Stop hook**: Prompt to save session as `discoveries/YYYY-MM-DD-session.md` with [[decision]] and [[function]] links

## Token Math (Obsidian Native)

| Query | Cost |
|-------|------|
| Full prose auth doc (1.2K) | 1K tokens |
| All auth files, compressed (10 files × 15 tokens) | ~150 tokens |
| Single function compressed | ~20 tokens |
| Function + deps + dependents, compressed | ~80 tokens |
| Tag query (#auth), compressed | ~150 tokens |
| Graph trace (structure only) | <10 tokens |

**Savings**: 85-98% by using compressed + lazy expansion.

## Why Obsidian?

1. **Already a knowledge graph** - wiki-links ARE the graph
2. **Visual** - Graph view is free knowledge exploration
3. **Collaborative** - Non-Claude humans can read/edit the vault
4. **Sync-free** - Just edit .md files, no separate backend
5. **Searchable** - Obsidian search + community plugins
6. **Versioned** - Git-friendly markdown files
7. **Portable** - Works with any markdown, no vendor lock-in
8. **Obsidian plugins extend** - Dataview, Smart Random Note, Knowledge Graph, Timeline, etc.
